## 🪟 修复 1: Windows 窗口动画

### 问题描述
- **最大化**: 界面完全刷新，相当于闪现再最大化
- **最小化**: 直接消失，没有动画过渡
- **原因**: 不像其他原生或非原生的 Windows 应用

### 根本原因分析

#### 1. window_manager 包的限制
```dart
// window_manager 包不提供动画 API
// 动画由 Windows DWM (Desktop Window Manager) 控制
```

#### 2. 完全透明窗口的问题
```dart
// 原始配置
WindowOptions(
  backgroundColor: Colors.transparent, // ❌ 完全透明
  // ...
)

// 问题：完全透明的窗口，系统 DWM 无法正确渲染动画
```

#### 3. 缺少内容过渡动画
```dart
// 原始代码
Container(
  decoration: BoxDecoration(
    color: Colors.black.withValues(alpha: 0.7),
    borderRadius: BorderRadius.circular(borderRadius),
  ),
  // ...
)

// 问题：窗口状态变化时，内容区域没有平滑过渡
```

### 解决方案

#### 1. 设置窗口背景色 (非完全透明)
```dart
// lib/ui/screens/windows_custom_window.dart
void _initWindow() async {
  // ...
  
  // [v2.2.8修复] 设置窗口背景色，确保系统 DWM 正确渲染动画
  await windowManager.setBackgroundColor(
    Colors.black.withValues(alpha: 0.01) // ✅ 非完全透明
  );
  
  // ...
}
```

**原理**:
- Windows DWM 需要非完全透明的窗口才能渲染动画
- alpha 0.01 几乎不可见，但足以让 DWM 识别
- 系统会自动处理最大化/最小化动画

#### 2. 使用 AnimatedContainer 平滑过渡
```dart
// lib/ui/screens/windows_custom_window.dart
@override
Widget build(BuildContext context) {
  final borderRadius = _isMaximized ? 0.0 : 16.0;
  
  return ClipSmoothRect(
    radius: SmoothBorderRadius(
      cornerRadius: borderRadius,
      cornerSmoothing: 1.0,
    ),
    child: Scaffold(
      backgroundColor: Colors.transparent,
      body: AnimatedContainer(
        // [v2.2.8修复] 添加动画过渡
        duration: const Duration(milliseconds: 200),
        curve: Curves.easeInOut,
        decoration: BoxDecoration(
          color: Colors.black.withValues(alpha: 0.7),
          borderRadius: BorderRadius.circular(borderRadius),
        ),
        child: Column(
          children: [
            _buildTitleBar(),
            Expanded(child: _buildContent()),
          ],
        ),
      ),
    ),
  );
}
```

**原理**:
- `AnimatedContainer` 自动插值动画
- 当 `_isMaximized` 变化时，圆角平滑过渡
- 200ms 动画时长，easeInOut 曲线

#### 3. 修复编译错误
```dart
// 错误的方法名
tray.startCourseReminderTimer(provider); // ❌

// 正确的方法名
tray.startCourseReminder(provider); // ✅

// 移除未使用的变量
bool _shouldReallyClose = false; // ❌ 删除

// 添加 mounted 检查
WidgetsBinding.instance.addPostFrameCallback((_) async {
  if (!mounted) return; // ✅ 防止异步错误
  // ...
});
```

### 技术细节

#### Windows DWM 动画机制
1. **检测窗口**: DWM 检测窗口是否支持动画
2. **透明度判断**: 完全透明的窗口被认为是"特殊窗口"，跳过动画
3. **渲染动画**: 非完全透明的窗口，DWM 自动渲染动画
4. **帧率控制**: 动画帧率由系统控制，通常 60 FPS

#### AnimatedContainer 原理
```dart
// 自动插值
borderRadius: 16.0 → 0.0 (最大化)
borderRadius: 0.0 → 16.0 (还原)

// 时间轴
0ms   → 开始
100ms → 中间帧
200ms → 结束

// 曲线
easeInOut: 慢 → 快 → 慢
```

## 📱 修复 2: 主界面滚动渲染

### 问题描述
- **现象**: 主界面触控拉伸拖动课程块时，课程会变得完全透明
- **缺失**: 没有模糊效果，没有玻璃效果
- **对比**: 日历和设置界面拖动正常，只有主界面有问题

### 问题澄清

#### 用户描述 vs 实际情况
```
用户描述: "拖动课程块时变透明"
实际情况: 代码中没有拖动功能，是滚动渲染问题
```

#### 代码检查结果
```dart
// 检查 android_liquid_glass_main.dart
// ❌ 没有 Draggable
// ❌ 没有 LongPressDraggable
// ❌ 没有 ReorderableListView

// 检查 weekly_schedule_grid.dart
// ❌ 没有拖动功能
// ✅ 只有 ListView 滚动
```

**结论**: 用户描述的"拖动"实际上是"滚动"时的渲染问题

### 根本原因分析

#### 1. Flutter 滚动优化机制
```dart
// Flutter 滚动时的优化策略
ListView.builder(
  itemBuilder: (context, index) {
    return CourseCard(...); // 每次滚动都重建
  },
)

// 问题：
// 1. 滚动时频繁重建 widget
// 2. 玻璃效果需要重新计算模糊
// 3. 性能优化导致降级渲染
```

#### 2. 重绘范围过大
```dart
// 原始代码
ListView.builder(
  itemBuilder: (context, index) {
    return LiquidCard(...); // 整个列表重绘
  },
)

// 问题：
// 1. 一个卡片变化，整个列表重绘
// 2. 玻璃效果计算开销大
// 3. 滚动时帧率下降
```

#### 3. 缓存范围不足
```dart
// 原始代码
ListView.builder(
  // 没有设置 cacheExtent
  itemBuilder: (context, index) {
    return CourseCard(...);
  },
)

// 问题：
// 1. 只渲染可见区域
// 2. 滚动时临时创建新卡片
// 3. 玻璃效果来不及计算
```

### 解决方案

#### 1. 使用 RepaintBoundary 隔离重绘
```dart
// lib/ui/widgets/weekly_schedule_grid.dart
Widget _buildCourseCard(BuildContext context, CourseEvent course) {
  // [v2.2.8修复] 使用 RepaintBoundary 隔离重绘
  return RepaintBoundary(
    child: GestureDetector(
      onTap: () => _showCourseDetail(context, course),
      child: Container(
        // 课程卡片内容
        // ...
      ),
    ),
  );
}
```

**原理**:
- `RepaintBoundary` 创建独立的渲染层
- 一个卡片变化，不影响其他卡片
- 玻璃效果只在自己的层内计算
- 滚动时保持已渲染的效果

#### 2. 增加 ListView 缓存范围
```dart
// lib/ui/screens/android_liquid_glass_main.dart
ListView.builder(
  padding: const EdgeInsets.fromLTRB(20, 12, 20, 20),
  physics: shouldDisableScroll 
      ? const NeverScrollableScrollPhysics() 
      : const BouncingScrollPhysics(),
  // [v2.2.8修复] 增加缓存范围
  cacheExtent: 200, // 提前渲染屏幕外 200px 的内容
  itemCount: courses.length,
  itemBuilder: (context, index) {
    final course = courses[index];
    // [v2.2.8修复] 使用 RepaintBoundary
    return RepaintBoundary(
      child: Padding(
        padding: const EdgeInsets.only(bottom: 16),
        child: liquid.LiquidCard(
          // ...
        ),
      ),
    );
  },
)
```

**原理**:
- `cacheExtent: 200` 提前渲染屏幕外 200px
- 滚动时，新卡片已经渲染好
- 玻璃效果提前计算完成
- 滚动流畅，无降级渲染

#### 3. 平板模式同样修复
```dart
// lib/ui/widgets/weekly_schedule_grid.dart
ListView.builder(
  padding: EdgeInsets.zero,
  physics: shouldDisableScroll 
      ? const NeverScrollableScrollPhysics() 
      : const AlwaysScrollableScrollPhysics(),
  // [v2.2.8修复] 增加缓存范围
  cacheExtent: 100, // 平板屏幕小，缓存 100px 即可
  itemCount: courses.length,
  itemBuilder: (context, index) {
    final course = courses[index];
    return Padding(
      padding: const EdgeInsets.only(bottom: 8),
      child: _buildCourseCard(context, course), // 已包含 RepaintBoundary
    );
  },
)
```

### 技术细节

#### RepaintBoundary 原理
```
Widget 树:
├─ ListView
│  ├─ RepaintBoundary (卡片 1) ← 独立渲染层
│  ├─ RepaintBoundary (卡片 2) ← 独立渲染层
│  └─ RepaintBoundary (卡片 3) ← 独立渲染层

重绘时:
- 卡片 1 变化 → 只重绘卡片 1
- 卡片 2、3 → 保持原有渲染
- 玻璃效果 → 不需要重新计算
```

#### cacheExtent 原理
```
屏幕可见区域: 800px
cacheExtent: 200px

渲染范围:
- 上方: -200px (屏幕外)
- 可见: 0px ~ 800px
- 下方: 800px ~ 1000px (屏幕外)

滚动时:
- 向下滚动 → 下方卡片已渲染
- 向上滚动 → 上方卡片已渲染
- 无需临时创建 → 流畅滚动
```

#### 性能权衡
```
优点:
+ 滚动流畅
+ 玻璃效果稳定
+ 用户体验好

缺点:
- 内存占用增加 (RepaintBoundary)
- 提前渲染消耗 CPU (cacheExtent)

结论:
✅ 权衡后，用户体验优先
✅ 内存和 CPU 占用在可接受范围
```
