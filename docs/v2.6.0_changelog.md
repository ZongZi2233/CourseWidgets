# CourseWidgets v2.6.0 更新日志

> 从 v2.5.9 升级至 v2.6.0 的完整变更记录

---

## 一、页面过渡动画

### `smooth_slide_transitions.dart`
- **移除黑色半透明遮罩层**：此前 `SmoothSlideTransitionsBuilder.buildTransitions()` 在 Push 动画中叠加了一个 `Container(color: Colors.black.withValues(alpha: 0.5))` 的 `FadeTransition`，导致所有推入的页面背景持续变暗。该遮罩仅在 Pop 动画反转时才消失，因此用户会发现"只有侧滑返回时背景亮度才恢复"。
- **保留 `secondaryAnimation` 渐隐逻辑**用于旧页面的层次感过渡，不再插入额外的黑色 Container。

### `custom_predictive_back_transitions.dart`
- **深色模式条件判断**：`CustomPredictiveBackTransitionState._buildOldPageTransition()` 中，暗色背景覆盖物现在仅在 `Theme.of(context).brightness == Brightness.dark` 时生效。浅色模式彻底取消遮罩。
- 清理了 `_borderRadiusTween`、`_opacityTween`、`_scaleTween`、`_positionAnimation` 等未使用字段（lint warning）。

## 二、教务系统课表提取 (WebView)

### `webview_import_screen.dart` — `_extractCourseTable()` JS 注入脚本完全重写

**根因修复**：原 JS 注入代码中声明了 `const currentUrl = window.location.href`，但后续两处条件判断均使用了未声明的变量 `url`（而非 `currentUrl`），导致 `ReferenceError` 被 `catch` 静默吞掉，EAMS 路径匹配永远不会执行。

**新增提取策略（按优先级排序）**：

1. **策略 1 — EAMS `table0.activities` 深度提取**
   - EAMS/树维教务系统在课表页面创建全局 `table0`（`CourseTable` 实例）
   - `table0.activities` 是一维数组，长度 = `weekDays × unitCounts`，每个元素是 `TaskActivity[]`
   - 遍历 `table0.activities[i]`，计算 `dayOfWeek = floor(i / unitCount) + 1`，`section = (i % unitCount) + 1`
   - 从每个 `TaskActivity` 对象提取 `courseName`、`teacherName`、`room`、`vaildWeeks`（EAMS 源码拼写）
   - 使用 `课名|教师|星期|节次|周次` 作为去重 key 避免同一个 `TaskActivity` 被多次推入
   - 先检测当前 `window`，再遍历所有 `<iframe>` 的 `contentWindow`

2. **策略 2 — HTML 课表表格直接返回**
   - 优先匹配 `id="manualArrangeCourseTable"`（EAMS 课表标准 ID）、`id="kbgrid_table"`（正方教务）、`id="courseTable"`
   - 回退为最大 `<table>`（`querySelectorAll('td').length > 20`）
   - 返回 `outerHTML` 的 Base64 编码供 Dart 端 `html_to_ics_converter` 解析

3. **策略 3 — 非课表页面检测**
   - 移动端 EAMS 会打开用户面板（`security/my`、`home!welcome`等）而非课表
   - 返回明确的中文错误提示：`当前页面不是课表页面。请在左侧菜单中点击【我的课表】后再提取。`

4. **策略 4 — 全页 HTML 回退**
   - 返回 `document.documentElement.outerHTML` 的 Base64 编码

### `_buildWebView()` — WebView 容器圆角
- Windows/macOS 端：`BorderRadius.circular(24)` → `BorderRadius.circular(12)`，更贴合桌面端窗口比例
- 移动端保持 `24`

## 三、Android 标题栏

### `android_liquid_glass_main.dart` — `_buildPageWithHeader()` 的 `GlassPanel` 参数调整

| 参数 | v2.5.9 | v2.6.0 |
|------|--------|--------|
| `glassColor` | `Colors.transparent` | 移除（使用默认值） |
| `blur` | `1.0` | `1.0` |

## 四、检查更新

### `settings_about_screen.dart`

- **语义化版本对比**：新增 `_isNewerVersion(String remote, String local)` 方法，将版本号按 `.` 分割为 `[major, minor, patch]` 并逐位比较。仅当远端版本严格大于本地版本时才判定为"有新版本"。解决了 v2.6.0 vs v2.5.9 被字符串不等判定为"有更新"的逻辑错误。
- **弹窗替代 Toast**：有新版本时弹出 `showDialog` + `LiquidCard`，显示：
  - 版本号标题（`发现新版本 vX.X.X`）
  - 当前版本号
  - GitHub Release body（可滚动文本区域，最高 240px）
  - "稍后" / "下载 APK/Windows 版" 双按钮
- **平台特定下载 URL**：`_buildDownloadUrl(String version)` 根据 `Platform.isWindows` 返回：
  - Windows: `Release_amd64_{ver}.zip`
  - Android: `app-arm64-v8a-release{ver}.apk`
- **下载跳转**：Windows 使用 `Process.run('cmd', ['/c', 'start', url])`，Android 使用 `Process.run('am', ['start', '-a', 'android.intent.action.VIEW', '-d', url])`
- 无更新时仅使用 `LiquidToast.success` 简洁提示

## 五、关于软件界面

### `settings_about_screen.dart`
- **全平台禁止滚动**：`ListView.physics` 从条件判断（仅 Android/iOS 横屏时 `NeverScrollableScrollPhysics`）改为全平台无条件 `NeverScrollableScrollPhysics()`。页面内容自适应布局。
- **LiquidToast 导入修复**：新增 `import '../widgets/liquid_toast.dart'`，此前通过 `liquid.` 前缀引用 `LiquidToast`，但该类不在 `liquid_components.dart` 中定义。
- **`GlassButton.onTap` 类型修复**：`_isCheckingUpdate ? null : _checkForUpdates` 中 `null` 不匹配 `VoidCallback`，改为 `() {}`。
- **`CircularProgressIndicator` const 修复**：移除 `color: AppThemeColors.babyPink`（非 const），使 `SizedBox` 外层的 `const` 修饰符合法。

## 六、配置持久化

### `schedule_config.dart` — `ScheduleConfigModel`
- **JSON 序列化/反序列化整数键修复**：`sectionStartTimes` 和 `sectionDurations` 的 `Map<int, int>` 在 `toJson()` 时隐式转为 `Map<String, dynamic>`。`fromJson()` 解码时未将 String key 解析回 int，导致 `TypeError`。
- 修复方式：`fromJson()` 中显式使用 `map.map((k, v) => MapEntry(int.parse(k.toString()), v as int))`。
- 该 Bug 导致所有用户自定义的课时配置（含"是否显示周末"开关）在重启后丢失并静默回退至默认值。

### `schedule_config_screen.dart`
- `_saveConfig()` 中确保 `showWeekends` 布尔值被传入并保存，而非遗漏。
